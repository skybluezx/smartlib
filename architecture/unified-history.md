# 统一版本与追溯：本地实施及边界

## 数据内容保护

V45—V47 只增加结构、函数、触发器和接口，没有 UPDATE 既有业务内容，也没有伪造历史原因或创建历史基线事实。迁移前后对 21 张关键业务表逐行计算内容摘要，再汇总比较行数及校验值：全部一致。校验包含名称、属性、版本、时间、关系、证据、别名、署名、来源、审核记录和全文资源引用。

历史表及审计表新加的关联列对旧记录为空。这是结构扩展，不表示历史上没有发生过修改。旧记录仍有原来的快照与批次属性，但不补写成新的 change_event。

## 存储契约

- `change_event`：一个数据库事务一个统一变更编号，保存执行身份、来源、原因及请求追踪编号。没有提供的原因留空。请求链路通过上下文变量传入事务；跨事务可按请求追踪编号关联，但不宣称跨事务原子性。
- `entity_revision.change_id`：该事务中已覆盖业务表产生的快照统一挂接变更编号。
- `entity_revision.submission_id`：通过通用变更流程提交或审核时直接关联申请。
- `audit.audit_event.change_id/submission_id`：同一事务中的操作审计挂接同一变更编号和申请。纯读取审计不凭空创建内容变更。
- 原来的 `before_value/after_value` 继续保存整行快照。关系—证据关联的复合键完整保存于快照中，`entity_id` 按关系 ID 分组。
- 新覆盖 `source_system`、`source_reference`、`relation_evidence`、`publication_fulltext_resource` 的 INSERT/UPDATE/DELETE。原有对象、关系、署名、证据、人物/机构扩展信息及名称变体等覆盖保持不变。
- 快照、审计、变更事件禁止普通 UPDATE/DELETE，并增加 TRUNCATE 拦截。管理员仍可通过停用触发器等手段突破，因此不等同于外部不可篡改存证。

## 页面与接口

入口仅保留在知识中枢：`/knowledge-hub/history`。按用户要求，学者星图前台的论文、学者、机构详情不展示“版本与追溯（治理）”链接。

默认看对象本身的技术版本；可以切换为包含关系、别名、证据等记录的时间线，分页读取。选择同一实体的两个历史状态可比较差异；复合键证据挂接只允许同一关联的状态比较。字段不存在与显式空值分别显示。关联的最近 20 条变更申请展示提交和审核身份、时间、意见及来源引用。

- GET `/api/v1/history/{object_id}`：`scope=object|all`，`limit=1..200`，`offset>=0`。
- POST `/api/v1/history/{object_id}/restore-proposal`：指定历史快照、前/后状态、字段、当前基础版本和原因，提交待审核变更。
- 历史接口要求变更审核权限，并检查当前对象及带可见性字段的历史快照访问范围；不向普通公开用户暴露旧内容。读取本身记录审计。

## 恢复原则

恢复不是删除新版本或直接覆盖整行。通过现有变更申请提交历史字段值，审核通过后产生新版本。版本冲突时拒绝覆盖。

页面提供规范名称、说明、关系置信度及人物/机构扩展字段的恢复；接口也支持领域规则允许且历史中确实存在的 attributes 字段。论文/期刊的专属字段、作者署名、机构关系主体或客体、别名集合、证据、文件及已删除对象，不通过此接口整行恢复，需要各自的治理流程。历史恢复并不等于全库任意时点恢复。

## 文件与备份

已只读核验本地全文桶：版本保留 Enabled，无生命周期自动过期规则。未改动任何 PDF。增加可重复执行的版本保留检查脚本；不自动清理历史或旧文件版本。

重写恢复演练入口：源库只读导出，恢复到本次生成的唯一临时数据库，检查对象校验值与追溯结构，再清理该临时库和临时文件；不再向源库插入测试记录，也不再强制删除固定名称数据库。

本次未设置定时备份、异地目的地、生产 WAL/PITR 或不可变对象锁。以上需要明确保存位置、保留期限及运维权限；桶版本保留不是异地备份，也不能复原之前已永久删除的版本。
