# D-10 任务执行首期验收方案 v1.0

- 状态：延后；D-10 恢复并确认路线后执行
- 日期：2026-08-26
- 候选对象：SmartLib PostgreSQL 持久任务 + Python worker + API/SSE + 首个真实任务场景

本方案不属于首次“学者星图” Demo 的验收范围，保留为 D-10 恢复后的实施门槛。

## 1. 必须贯通

1. 创建任务返回稳定 job ID 和幂等响应；
2. 两个 worker 并发时每个 attempt 只有一个有效 lease owner；
3. worker 崩溃、lease 到期后任务可安全接管；
4. step/progress/event 从数据库事实经 API/SSE 到 Web；
5. succeeded/failed/cancelled/retry_wait 均有真实状态路径；
6. 任务只读自己的 RLS 数据，worker 使用独立最小权限；
7. synthetic 任务、数据、预制输出和未调用模型边界明确显示。

## 2. 绝对门槛

- 相同幂等键产生重复业务副作用；
- 两个 worker 同时持有有效 lease 并成功提交同一 attempt；
- worker 崩溃后任务永久停在 running；
- 不可重试错误无限重试或重试无上限；
- 取消后仍把任务标记成功且不记录竞态结果；
- 终态可被普通 API 改回 running/queued；
- 任务输入允许任意命令、模块、URL 或 handler；
- 用户可读取其他 synthetic actor 的私有任务/产物；
- payload/secret/许可正文进入日志、SSE 或错误；
- Web 用定时器伪造数据库中不存在的步骤/进度；
- 预制 synthetic 结果被表述为真实 AI 实时生成。

## 3. 故障哨兵

- 两个/三个 worker 竞争同一批 queued jobs；
- 领取后 kill、执行中 kill、提交前网络断开；
- handler 成功但确认超时、外部副作用成功但 worker 重启；
- transient/permanent/validation/permission/cancelled 错误分类；
- lease 心跳延迟、时钟偏差、过期接管；
- 同一幂等键并发提交、不同用户相同 key；
- 取消发生在 queued/running/retry_wait/完成临界点；
- SSE 断线重连、last event ID、重复事件；
- 数据库恢复后 queued/running/retry_wait 任务一致。

## 5. 自动化与运行证据

- migration/约束/RLS/并发数据库测试；
- 状态机 property-based 测试；
- handler registry、schema、错误分类、幂等单元测试；
- 多 worker 进程竞争、kill/restart 和 lease 接管集成测试；
- FastAPI create/get/list/cancel/SSE 契约和越权测试；
