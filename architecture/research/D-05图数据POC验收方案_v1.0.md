# D-05 图数据 POC 验收方案 v1.0

> **历史文档：** 本文原 Neo4j 验收对象已于 2026-09-01 被 ADR-0013 取代。
> 当前验收对象为 HugeGraph 1.7 与 PostgreSQL 18 基线；以下 Neo4j 条目仅保留历史证据，
> 不再是现行部署或实施要求。

- 状态：原路线已被 ADR-0013 取代，仅保留历史
- 日期：2026-08-25
- 对比对象：Neo4j 专用图投影、PostgreSQL 18 规范关系基线；AGE 满足准入条件后加入

## 1. 目标与边界

本 POC 判断专用图引擎是否能在 SmartLib 真实关系场景中提供足以覆盖额外许可和运维成本的收益。它不比较厂商演示数据，也不允许图产品成为权威关系来源。

## 2. 三个必须贯通的业务场景

1. 多跳合作路径：学者—成果—项目—机构，返回每一步的关系和证据。
2. 学科—团队—资源证据链：解释某资源为何推荐给某学科/团队。
3. 成果—能力—需求候选匹配：明确区分业务事实、算法推断和人工确认关系。

每个场景必须从同一 Public API 契约调用，Web 只消费 API；未来 MCP、Skill、Agent 不接触图 DSL。

## 3. 数据集分层

- 机制集：少量合成数据，覆盖环、自环、平行边、孤立节点、高度数节点、撤回和乱序事件；
- 授权样本集：学校允许用于 POC 的真实对象、关系和证据；
- 规模集：保持度分布和权限分布的脱敏/合成扩展数据；
- 权限哨兵集：公共、校内、受限、私有以及不同许可用途组合。

清单记录节点数、边数、类型分布、度数分位数、连通分量、来源、许可、展示字段、可否进入图投影和保留期限。

## 4. 绝对门槛

以下任一失败即不得接受该候选为首版图底座：

1. 返回任何无权访问的节点、边、证据、属性、计数、路径存在性或最短路径长度；
2. 路径包含不可见中间节点/边，但仅隐藏该元素后仍返回残缺路径；
3. 权限撤销、关系撤回或对象删除超过确认窗口后仍可查询；
4. 重复、乱序或重放事件导致错误最终图，且无法自动纠正；
5. 不能从 PostgreSQL 权威状态全量重建，或重建后节点、边、版本、策略和证据引用不一致；
6. 备份恢复、版本升级、固定制品或许可不满足学校生产要求；
7. 产品 DSL 或驱动类型泄漏到公共 API。

## 5. 查询矩阵

| 类别 | 验证内容 |
|---|---|
| 邻域 | 1–2 跳、方向、关系类型、节点类型、时间和审核过滤 |
| 路径 | 最短路径、限定路径、无路径、多个等长路径、环 |
| 证据 | 边到证据、来源、事实类别、模型/规则版本 |
| 时间 | 当前有效、历史时点、撤回、未来生效 |
| 权限 | 节点/边/证据分别受限，中间元素受限，计数与存在性 |
| 高度数 | 学科、机构等超级节点的分页、超时和资源上限 |
| 更新 | 单边 upsert/delete、节点删除、许可变更、乱序与重放 |
| 重建 | 全量重建、增量追平、版本别名/切换、失败恢复 |

## 6. 指标

### 正确性与治理

- 与 PostgreSQL 权威基线结果集合一致率：100%；
- 未授权返回或侧信道泄漏：0；
- 节点、边、证据与策略版本一致率：100%；
- 删除/撤回清除率：100%；
- 路径解释中的证据覆盖率和事实类别完整率：100%。

### 性能与成本

- 各查询类别 p50/p95/p99、超时率和吞吐；
- 随节点数、边数、平均/最大度数和跳数的增长曲线；
- 构建/重建时长、增量投影延迟、CPU、内存、磁盘；
- 权威 PostgreSQL 在 baseline 图查询负载下的事务延迟变化；
- 单机 POC、首版生产 HA、备份、监控、支持和许可总拥有成本。

业务并发、路径深度和失效 SLO 必须由试点场景确认，POC 先生成曲线，不虚构阈值。

## 7. AGE 准入条件

AGE 加入同场评测前必须同时满足：

1. 固定 PG18 稳定发布制品而非浮动源码或仅 RC 标签；
2. 在 SmartLib PG18 镜像上完成安装、升级和卸载演练；
3. 非超级用户运行、RLS、备份/PITR 和连接池行为通过测试；
4. 使用独立 PG18 图投影实例，不直接把扩展故障域引入权威主库；
5. Python 3.14 驱动和参数化查询路径可维护。

## 8. 选择规则

1. 先过安全、重建、恢复和许可绝对门槛。
2. 再比较三个真实业务场景的正确性、可解释性、延迟和开发维护成本。
3. 专用图引擎收益不足以覆盖新增系统或商业能力成本时，首版使用 PostgreSQL 基线。
4. Neo4j Community 功能通过但生产必须依赖 Enterprise 时，先取得正式报价与权益清单，再决定采购或改选。
5. AGE 在稳定性和隔离运行上达标且查询性能足够时，可优先低许可成本路线。
6. NebulaGraph 只在规模曲线证明单实例/PG 路线无法满足时进入下一轮。

## 9. 输出证据

- 数据与许可清单、查询集和期望路径；
- 固定镜像/制品摘要、配置、schema/约束和查询模板；
- 自动化权限、契约、投影、乱序、删除、重建和恢复报告；
- 性能与资源曲线；
- Neo4j Community/Enterprise 权益和报价边界；
- AGE PG18 制品、升级、RLS 和备份核验；
- 接受/否决理由及退出方案。

## 10. 当前执行结果（2026-08-26）

| 项目 | 当前结果 | 边界 |
|---|---|---|
| 固定制品 | `neo4j:2026.07.1-community`；本地镜像摘要已记录 | 仍需形成正式供应链镜像仓库与漏洞治理流程 |
| 权威与投影 | PostgreSQL 保存对象、关系、证据；Outbox 投影到 Neo4j | Neo4j 不承担权威写入 |
| 公共契约 | 邻域、有限路径、关系解释均通过统一 API/`GraphPort` | 未暴露 Cypher 或驱动类型 |
| 真实运行切片 | PostgreSQL 与 Neo4j 均跑通三节点、两关系、两跳路径 | 属于平台纵向切片，不代替三个完整业务场景 |
| 私有中间节点 | 拥有者可见完整路径；非拥有者看不到该路径及残缺结果 | 通过首轮哨兵验证 |
| 私有证据 | 同一公开关系中，拥有者可见证据 ID，非拥有者返回空列表 | 通过 PostgreSQL 与 Neo4j 双后端验证 |
| Web 展示 | 基础设施页读取统一图能力，展示节点、关系、事实类别、证据数和投影版本 | 当前默认读取 PostgreSQL 基线，可配置切换 Neo4j |

阶段 A 尚未关闭的项目：三个授权真实业务场景、环/平行边/撤回/乱序全集、全量重建与恢复、规模与延迟曲线、Community/Enterprise 权益和总拥有成本。未完成这些项目之前，不作生产采用结论。
