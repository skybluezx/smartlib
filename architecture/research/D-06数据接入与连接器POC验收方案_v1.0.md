# D-06 数据接入与连接器 POC 验收方案 v1.0

- 状态：已延后；Demo 阶段不执行，首批真实数据接入前重新启用并更新版本
- 日期：2026-08-26
- 对比对象：SmartLib Python 原生连接器、Apache SeaTunnel 2.3.13/Zeta；Airbyte/NiFi 满足触发条件后加入

## 1. 目标

验证统一 SmartLib 接入契约能否让不同执行器安全、可恢复地接入同一真实数据源，并保留来源、许可、清单、检查点和发布证据。POC 不允许用页面硬编码、一次性脚本或直接写权威对象表代替真实接入链路。

## 2. 数据集

### 2.1 机制集

- 受控 CSV/JSON 文件：正常、重复、空文件、截断、编码错误、列顺序变化、增删字段、类型变化；
- 模拟 API：分页、游标、限流、401/403、429、5xx、超时、部分页失败、重复记录；
- 测试数据库：快照、插入、更新、删除、无主键表、长事务、断线、CDC 位点恢复。

### 2.2 授权真实源

至少一个学校正式 API/交换文件源；只有获得书面授权和字段许可后才能加入。若提供 CDC，再增加一个获授权数据库源。记录责任部门、接口负责人、用途、字段、更新量、保存期限和展示边界。

每个候选源先完整填写《D-06 首批真实数据源准入与信息采集表 v1.0》，通过授权、安全连接、稳定标识与追溯三个准入门后，才可进入本验收集。

## 3. 共同查询与操作集

所有执行器必须通过同一控制面完成：

1. `probe`：连接、身份、授权、配额和版本检查；
2. `discover`：数据集、模式、主键、增量方式和模式指纹；
3. 创建全量运行并生成分区；
4. 暂停、失败、重试和取消；
5. 从已确认检查点恢复增量；
6. 生成并核对 manifest；
7. 将合格接入记录发布为规范对象/关系/证据；
8. 从任一规范结果追溯到接入记录、运行、数据集和数据源。

## 4. 绝对门槛

以下任一失败即不得接受候选为生产接入执行器：

1. 接入超出授权数据集、字段、时间范围或用途的数据；
2. 配置、日志、错误、清单、API 或 UI 出现明文凭据；
3. 部分失败后仍把运行标记成功或推进全局检查点；
4. 重试/重放产生重复规范对象、关系或证据；
5. 删除、撤回或许可到期未在约定窗口传播；
6. 模式变化导致字段静默丢失、截断或错误类型转换；
7. 不能核对输入/接受/拒绝/发布数量和校验和；
8. 规范结果不能回溯到数据源、数据集、运行和原始外部标识；
9. 执行器直接修改权威对象模型或绕过质量/许可发布门；
10. 不能从持久检查点恢复，或升级后无法继续/安全重建。

## 5. 测试矩阵

| 类别 | 验证内容 |
|---|---|
| 发现 | 模式、主键、增量能力、源版本、字段许可 |
| 全量 | 分区、分页、范围、数量、校验和、重复运行 |
| 增量 | 游标/时间戳/CDC、插入更新删除、乱序、迟到数据 |
| 恢复 | worker 崩溃、网络中断、源重启、平台重启、集群全停 |
| 漂移 | 加列、删列、改名、类型变化、主键变化 |
| 治理 | 许可、用途、可见性、保留期、责任人、审计 |
| 安全 | 密钥引用、最小权限、出站白名单、日志脱敏、恶意文件 |
| 发布 | 质量隔离、人工批准、幂等规范化、Outbox 投影 |
| 运维 | 心跳、进度、错误分类、重试、取消、告警、运行手册 |
| 退出 | 导出清单/检查点、替换执行器、全量重建 |

## 6. 指标

### 正确性与治理

- 授权范围外记录/字段：0；
- 明文凭据泄漏：0；
- 接收、拒绝、发布数量可核对率：100%；
- 重放后规范结果集合一致率：100%；
- 删除/撤回传播正确率：100%；
- 来源、运行、许可和外部 ID 追溯覆盖率：100%；
- 未经审核模式漂移进入正式区：0。

### 性能与成本

- 全量和增量吞吐、p50/p95 单批延迟、限流等待；
- 检查点间隔、恢复时间、积压追平时间；
- CPU、内存、临时磁盘、网络和持久状态空间；
- 单连接器开发/升级/故障处理工时；
- 原生 worker 与 SeaTunnel 的新增部署、制品、监控和安全成本。

不在缺少真实数据量和更新目标时虚构吞吐或 SLO 门槛。

## 7. SeaTunnel 专项

- 固定 2.3.13 二进制、插件、JDBC 驱动和摘要；
- Zeta 单节点机制 POC 后，再验证多节点共享 checkpoint/MapStore；
- REST API 网络隔离、认证和作业提交白名单；
- 快照到增量切换、checkpoint/savepoint 与集群全停恢复；
- 插件隔离、驱动冲突、版本升级和回退；
- SeaTunnel 输出到 SmartLib 接入信封/落地区，不直写权威对象表。

## 8. 选择规则

1. 先通过安全、许可、正确性、追溯和恢复绝对门槛。
2. 首批特殊 API/资源连接器优先原生 SDK，除非第三方有经过验证的直接收益。
3. SeaTunnel 在标准 JDBC/文件/CDC 上显著减少开发维护成本且状态恢复可靠时，作为第二执行器保留。
4. 首批源无 CDC 或规模不足时，不因产品具备 CDC 就提前生产化集群。
5. Airbyte/NiFi 只有触发条件成立才加入，不用连接器数量或可视化演示替代真实源适配证据。

## 9. 输出证据

- 数据源授权与字段许可清单；
- 连接器能力描述、模式指纹和接入信封样例；
- 固定制品、依赖、许可证、SBOM/漏洞核验记录；
- 全量/增量/删除/漂移/失败/恢复自动化报告；
- manifest 对账和规范结果追溯报告；
- 性能与资源曲线；
- 运行、升级、回退、密钥轮换和退出手册；
- 接受/否决结论与下一阶段角色。
