# D-05 图数据与知识网络技术选型调研 v1.0

> **历史文档：** 本文记录 2026-08-25 的 Neo4j POC 选型过程。该产品选择已于
> 2026-09-01 被 ADR-0013 取代；当前唯一专用图投影为 Apache HugeGraph 1.7，
> PostgreSQL 18 仍是权威与降级基线。以下 Neo4j 内容仅用于保留决策历史。

- 状态：已被 ADR-0013 取代，仅保留历史
- 日期：2026-08-25
- 关联决策：D-05、ADR-0006（提议）
- 决策结论：Neo4j Community 固定版本作为专用图引擎 POC 主路线；PostgreSQL 18 规范关系表作为权威基线；Apache AGE 1.8/PG18 仅在正式稳定制品和升级路径核验后进入兼容性副线；NebulaGraph 暂不进入首轮 POC

## 1. 这项决策解决什么

SmartLib 的知识网络不是一个只供 Web 画图的 JSON 数据集。它要向 Web、Public API、MCP、Skill、Agent、小程序和客户端提供同一组受治理关系能力：

- 查询对象的一跳邻域，并按关系类型、对象类型、时间和审核状态过滤；
- 查找有限跳数的合作路径、学科—团队—资源证据链；
- 为成果—能力—需求匹配提供候选路径和可解释证据；
- 返回每条边的规范关系 ID、关系类别、事实等级、审核状态、证据 ID 和版本；
- 在遍历前过滤不可见节点与边，在返回后再次拒绝不完整或越权路径；
- 由 PostgreSQL 权威事实和 Outbox 全量重建，图产品不能成为唯一事实来源。

D-05 选择的是“图查询投影如何实现”，不改变 PostgreSQL 18 保存关系断言和证据的 D-03 决策。

## 2. 当前系统事实

当前数据库已经有可持续演进所需的规范关系基础：

- `knowledge_object` 保存稳定对象 ID、类型、可见性、质量、审核和双时间边界；
- `relation_assertion` 保存主语、谓词、对象/字面量、事实类别、置信度、许可标签、审核状态、模型版本和双时间边界；
- `relation_evidence` 将每一关系连接到来源证据；
- PostgreSQL RLS 已覆盖对象、关系和关系证据；
- Outbox 与独立投影 worker 已在 D-04 形成可复用实现模式。

仍缺少真实关系数据规模、平均/最大度数、热点超级节点、典型路径长度、目标并发、采购预算、HA/RPO/RTO 和学校是否已有图平台。因此现在可以确认 POC 路线和稳定契约，不能直接宣称生产产品胜出。

## 3. 候选方案

### A. Neo4j Community（推荐专用图 POC 主路线）

适合点：

- 原生属性图、Cypher、ACID 事务和官方 Python Driver，适合快速实现和审阅多跳查询；
- 专用图存储可与 PostgreSQL 权威事务负载隔离；
- 开发工具与查询解释能力成熟，便于把真实路径查询做成可复现实验；
- Community 可覆盖单实例 POC 和功能验证。

必须正视的边界：

- 官方当前文档明确 Community 面向单实例；集群、故障转移、在线备份、RBAC、属性级和子图访问控制属于 Enterprise 范围；
- Community 是 GPLv3，生产采用前仍需结合部署、分发和修改方式完成法务核验；
- SmartLib 不能依靠 Community 数据库内的细粒度授权。只允许专用投影账号访问，所有用户查询必须经过平台 `GraphPort`，查询前后双重校验；
- POC 通过不等于自动采购 Enterprise。HA、安全、备份和支持成本要单独形成生产决策。

### B. PostgreSQL 18 规范关系表（强制同场基线和降级路径）

适合点：

- 当前模型、RLS、证据链和双时间已经落地，无新增产品；
- 递归 CTE 足以验证有限跳路径、邻域和证据链的正确语义；
- 最适合充当权威结果集和小规模首版退路。

风险：

- 高度数、多跳、路径枚举和图算法可能消耗权威库资源；
- SQL 实现复杂度会随路径约束和算法种类快速增长；
- 即使小规模性能足够，也不能据此推导长期大图能力足够。

### C. Apache AGE 1.8 / PostgreSQL 18（兼容性副线，不建议当前主线）

适合点：

- Apache 2.0；在 PostgreSQL 内提供 openCypher 与 SQL 混合查询；
- 当前项目 README 已声明支持 PostgreSQL 18；2026 年发布页出现 PG18 1.7 和 1.8 候选制品；
- 近期版本加入了 RLS 与权限检查修复，方向上更接近 SmartLib 的治理要求。

当前风险：

- 官方网站安装文档仍只写 PostgreSQL 11–15，而仓库 README 写到 18，文档与发布状态存在漂移；
- PG18 1.8 当前可见制品仍带 `rc0` 标记，不能把源码主分支兼容性等同于稳定生产支持；
- 安装扩展、升级脚本、非超级用户加载、备份恢复和 RLS 语义都必须在与 SmartLib 完全一致的 PG18 镜像上验证；
- 把图负载和扩展故障放入权威主库会扩大故障域。即使选 AGE，也建议先使用独立 PG18 图投影实例，而不是直接改造权威数据库。

### D. NebulaGraph 3.8（规模触发候选，首轮不引入）

适合点：分布式 shared-nothing 存储、Raft、多副本和水平扩展适合超大图。

不适合当前首轮的原因：官方生产建议包含 3 个 metad、至少 3 个 storaged、至少 3 个 graphd，并给出 48 核、256 GB、NVMe SSD 的生产资源建议；当前没有任何 SmartLib 规模证据支持承担这套复杂度。只有节点/边数量、热点度数或 SLA 证明 Neo4j/AGE/PG 基线不足时再加入同一 POC。

## 4. SmartLib 比较矩阵

| 维度 | Neo4j Community | PostgreSQL 18 关系表 | Apache AGE/PG18 | NebulaGraph 3.8 |
|---|---|---|---|---|
| 当前角色 | **专用图 POC 主路线** | **权威基线/退路** | 兼容性副线 | 规模触发候选 |
| 查询语言 | Cypher | SQL/递归 CTE | SQL + openCypher | nGQL |
| 权威事实 | 否，只做投影 | 是 | 仍应只做独立投影 | 否，只做投影 |
| POC 部署复杂度 | 中 | 最低 | 中，需编译/扩展治理 | 高 |
| 生产 HA | Community 不提供集群 | 继承 PG 路线 | 继承独立 PG 实例能力，扩展需验证 | 原生分布式 |
| 细粒度数据库授权 | Enterprise 能力；Community 不足 | 现有 RLS | 新近 RLS 支持，必须实测 | 需按实际版本/许可核验 |
| 多跳开发体验 | 强 | 中低 | 中高 | 中 |
| 与权威库故障隔离 | 强 | 无 | 仅独立实例时有 | 强 |
| 当前最大风险 | 生产许可与企业能力成本 | 图负载影响主库 | PG18 制品与升级成熟度 | 过度架构和运维成本 |

## 5. 推荐决策

建议项目负责人确认：

> SmartLib 采用 Neo4j Community 固定版本作为 D-05 专用图投影 POC 主路线，以 PostgreSQL 18 规范关系表/递归查询作为同场正确性与低复杂度基线；Apache AGE 1.8/PG18 仅在稳定制品、升级、RLS、备份和独立实例运行验证完成后加入副线；NebulaGraph 暂不进入首轮。POC 通过后再决定首版采用 Neo4j、AGE 独立投影或 PostgreSQL 基线，不提前承诺 Neo4j Enterprise 采购。

推荐理由不是“Neo4j 最强”，而是它能最清楚地验证专用图引擎是否给 SmartLib 的三个真实关系场景带来足够收益，同时不污染已确认的 PostgreSQL 18 权威主库。AGE 的 PG18 状态正在改善，但当前正式制品与文档一致性不足以让它承担主路线。

## 6. 产品无关稳定契约

无论选择哪种产品，首期冻结：

1. `GraphPort` 只暴露领域操作，不暴露 Cypher、SQL、nGQL 或产品驱动对象。
2. 首批能力为 `get_knowledge_neighborhood`、`find_knowledge_paths`、`explain_relation`；不开放任意图查询接口。
3. 请求限定起点/终点对象、允许关系类型、方向、时间点、最大跳数和结果上限；最大跳数由服务端设置硬上限。
4. 身份、组织、角色、许可用途、网络和策略版本由可信入口注入，客户端输入不能升级为授权事实。
5. 节点和边都必须可见，路径中任何中间节点、边或证据无权访问时整条路径拒绝返回。
6. 计数、候选数量、最短路径长度、解释和“是否存在路径”同样属于受保护信息，不能形成侧信道。
7. 返回稳定对象 ID、关系 ID、对象/关系/证据版本、投影版本和证据 ID；不默认返回未经许可的证据正文。
8. PostgreSQL 业务事务与 Outbox 原子提交；图投影按关系 ID 幂等 upsert/delete，支持乱序保护、权限撤销和全量重建。
9. 所有入口共享能力目录和 OpenAPI；MCP/Skill/Agent 只能调用受限领域工具，不能提交原始图 DSL。

## 7. 决策后首期开发任务

确认 POC 路线后启动：

1. 增补关系创建/审核/撤回事件以及图投影独立回执；
2. 建立 `GraphPort`、PostgreSQL baseline adapter 和双层权限校验服务；
3. 发布三个只读图能力 API 与能力目录；
4. 建立 Neo4j POC profile、固定镜像摘要、唯一约束、索引、读写账号和投影 worker；
5. 使用少量明确标记的授权/合成关系形成真实 API + Web 知识网络纵向切片；
6. 运行权限、路径、删除、乱序、重建、恢复、延迟和资源测试；
7. 获得真实学校关系数据后进入产品胜负评测。
