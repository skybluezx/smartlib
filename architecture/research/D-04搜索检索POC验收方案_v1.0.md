# D-04 搜索检索 POC 验收方案 v1.0

- 状态：已确认，进入工程基线实施；真实相关性阶段等待授权样本
- 日期：2026-08-25
- 对比对象：OpenSearch 3.8.x；PostgreSQL 18 FTS + pgvector 0.8.6
- 条件对象：学校已有 Elasticsearch 9.4.x 平台时加入

## 1. 验证原则

1. 同一数据、同一查询、同一相关性判断、同一硬件资源预算。
2. 先验权限范围完全相同；不得用后过滤掩盖召回阶段泄漏。
3. 词法、向量、混合分开报告，不能只展示最优参数结果。
4. 真实数据不足时，只能完成契约/安全工程验证，不能宣布相关性选型完成。
5. 所有版本、配置、分析器、词典、模型、切片、索引参数和运行时间可复现。

## 2. 两阶段数据集

### A. 工程数据集

目的：验证契约、索引、权限、重建、故障和自动测试。可使用经标注的非敏感演示记录，但不能冒充真实业务证据。

- 至少覆盖学者、成果、项目、专利、资源、需求六类对象；
- 每类同时包含公开、组织内、个人、合同受限和过期许可记录；
- 含同名、别名、缩写、中文术语、英文术语、DOI/项目号等边界样本；
- 含更新、删除、策略变更、来源撤回和重复事件。

### B. 真实评价数据集

目的：完成产品选择。需要学校授权，建议 500–2,000 个代表性对象、至少 100 条查询，并覆盖六类对象与不同可见范围。

每条查询由业务专家按 0–3 级标注：

- 0：不相关；
- 1：弱相关；
- 2：相关；
- 3：高度相关/正确目标。

至少两名标注者处理关键查询；分歧需记录仲裁结果。数据清单记录来源、许可、是否可全文索引、是否可向量化、允许的展示字段和保留期限。

## 3. 查询集分类

| 类别 | 示例意图 | 主要验证点 |
|---|---|---|
| 精确标识符 | DOI、项目号、工号、专利号 | Top-1、字符归一化 |
| 人名/机构名 | 中文名、曾用名、英文名、院系简称 | 别名、歧义、字段权重 |
| 专业短语 | 学科术语、疾病名、技术名 | CJK/ICU/词典、短语匹配 |
| 中英混合 | 中文主题 + 英文缩写 | 多字段分析与归一化 |
| 语义改写 | 不含原词但意图相近 | 向量召回增益 |
| 结构化筛选 | 类型、组织、年份、来源、审核状态 | 过滤、分面、计数 |
| 许可约束 | 不同用户/用途/网络下同一查询 | 零泄漏、拒答原因 |
| 负向查询 | 不存在或无权访问 | 空结果、不可推断存在性 |
| 更新与撤回 | 许可到期、对象删除、证据撤回 | 新鲜度与一致性 |
| 深分页/聚合 | 多页浏览与分类统计 | 排序稳定、聚合不泄漏 |

## 4. 待实现的稳定查询契约

### 输入

- `query_text`
- `object_types[]`
- `filters`：来源、组织、年份、审核状态等允许字段
- `retrieval_mode`：`lexical | semantic | hybrid`
- `page_size` 与游标
- `purpose`：由可信调用链约束
- 身份、角色、组织、网络和许可上下文：仅由网关/策略服务注入

### 输出

- `object_id`、`object_type`
- 标题、经许可的摘要与高亮
- `evidence_ids[]`
- `object_version`、`projection_version`
- `recall_channels[]`：lexical / semantic / relation（后续）
- 可解释排序信息；不得把产品原始 DSL 暴露为公共契约
- `next_cursor` 与安全过滤后的聚合

索引文档建议包含稳定对象 ID、类型、规范名、别名、许可字段、可聚合字段、证据引用、对象/策略/投影版本、文本字段，以及带模型 ID/版本的向量。向量字段不能进入默认响应。

## 5. 绝对门槛

以下任一失败即不能进入首版实施：

1. 任一查询、向量召回、自动补全、聚合、总数、分页或解释接口出现未授权对象、字段或存在性泄漏。
2. 权限撤销、许可到期或对象删除超过已确认失效窗口仍可检索。
3. 无法从权威数据全量重建，或重建后对象集合、版本和策略不一致。
4. 重复/乱序 Outbox 事件造成错误最终状态，且无法自动修复。
5. 产品/插件许可、电子资源合同或数据出域规则不允许目标部署方式。

## 6. 评价指标

### 质量

- NDCG@10：主相关性指标；
- MRR@10：精确对象和导航型查询；
- Recall@50：候选召回完整度；
- Exact Top-1：DOI、项目号等精确标识符，目标 100%；
- 零结果率、错误高亮率、过滤后结果不足率；
- 词法、语义、RRF、分数融合分别报告，禁止只报混合最优值。

混合路线应相对最佳词法基线取得有统计和业务意义的增益，且不得降低精确标识符、姓名和许可查询。具体最低增益由真实查询集建立后冻结，不能现在凭空设定。

### 安全与一致性

- 未授权返回数：0；
- 未授权聚合/总数泄漏：0；
- 投影覆盖率、删除清除率、版本一致率：100%；
- 权限失效窗口：由学校 SLO 确认；POC 先记录可达值，不把未经确认的数字冒充需求。

### 性能与成本

- p50、p95、p99 延迟与错误率；
- 固定并发下吞吐；
- CPU、内存、磁盘、索引体积、索引/重建耗时；
- 高选择性许可过滤（例如仅 1%、10%、50% 文档可见）下的延迟、Recall@50 和实际结果数；
- 权威 PostgreSQL 在搜索负载下的事务延迟变化。

目标并发和延迟 SLO 必须由用户规模、展示场景和试点要求确定。POC 先生成容量曲线，不用任意阈值替代业务决策。

## 7. 对比矩阵

每个候选至少运行：

1. 精确/字段加权 BM25 或对应 FTS 基线；
2. 纯向量精确检索（小规模 ground truth）；
3. ANN 检索；
4. ANN + 1%/10%/50% 可见性过滤；
5. 关键词 + 向量 RRF；
6. 关键词 + 向量分数归一化/加权融合；
7. CJK、ICU 和候选 PostgreSQL 中文方案；
8. 冷启动、稳定运行、重建后首次查询；
9. 单对象更新、批量导入、许可撤销、删除和重复事件；
10. 快照/备份恢复与版本化索引别名切换。

嵌入模型固定为同一经批准的本地多语种基线，记录模型、维度、池化、归一化和切片版本。模型优劣不纳入本轮引擎胜负。

## 8. 选择规则

1. 先过安全、许可、重建和一致性绝对门槛。
2. 再比较真实查询上的相关性，不以单次演示主观判断。
3. 质量近似时，选择总拥有成本更低、学校更能持续运维的方案。
4. OpenSearch 的独立扩容和检索质量收益不足以覆盖新增运维时，首版选择 PostgreSQL 适配器。
5. PostgreSQL 路线造成权威事务明显退化、中文检索不足或混合/聚合复杂度不可控时，选择 OpenSearch。
6. 结论必须记录原始结果、配置、失败项和适用规模，并更新 ADR-0005。

## 9. 输出证据

- 授权数据清单和脱敏/许可说明；
- 查询集、相关性判断和仲裁记录；
- 可复现环境版本、镜像摘要、索引模板和参数；
- 自动化安全、契约、投影和重建报告；
- 相关性与容量结果；
- 资源成本估算、运维责任和故障恢复记录；
- 接受/否决理由及首版实施范围。

## 10. 当前执行状态（2026-08-25）

阶段 A“契约、投影与引擎机制”已完成：稳定搜索契约、PostgreSQL 基线适配器、OpenSearch 3.8.0 适配器、Outbox 双投影、严格映射、读写别名、API 权限隔离、分面零泄漏和过滤式 k-NN 机制均已验证。

阶段 B“学校真实数据对比”尚未开始。其启动输入是经授权的数据清单、许可矩阵、冻结查询集、专家标注安排和可执行的业务 SLO。阶段 B 前保持 PostgreSQL 为默认后端，OpenSearch 仅通过 `search-poc` profile 启动。
