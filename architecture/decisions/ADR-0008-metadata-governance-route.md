# ADR-0008：元数据与治理平台路线

- 状态：已接受，首期基线已实现
- 日期：2026-08-26
- 决策人：项目负责人（用户）
- 关联编号：D-07

## 背景

SmartLib 的来源、电子资源许可、质量、责任、证据、审核和审计是学校知识基础设施的核心业务语义。当前已有来源、来源引用、证据、策略标签和审计基础，但治理页仍使用前端模拟数字，缺少资产、数据契约、许可台账和质量问题闭环。

由于 D-06 真实外部接入已延后，当前没有足够技术元数据支撑部署完整目录平台。Demo 仍需要真实治理能力，不能整体跳过 D-07。

## 决策

采用 SmartLib 最小治理域作为当前权威主路线，在 PostgreSQL 18 + FastAPI 中建设来源、资产、数据契约、电子资源许可、质量、责任、变更和审计闭环。

OpenMetadata POC 延后到首批真实数据源和技术元数据进入后；届时只作为技术目录、血缘和通用质量加速器评估。DataHub 和 Apache Atlas 暂不进入首轮。

该路线由项目负责人于 2026-08-26 确认。当前开发不得以“未来会部署 OpenMetadata”为由跳过 SmartLib 权威治理域，也不得在真实技术元数据尚未进入时提前部署 OpenMetadata。

## 必须保持的边界

- SmartLib 权威保存电子资源许可、知识证据、画像版本、对象/关系审核与模型用途；
- 通用元数据产品不成为应用查询的唯一治理来源；
- 外部产品通过 `MetadataCatalogPort` 交换技术元数据，不把其实体/URN/驱动类型泄漏到 Public API；
- 来源、许可、质量、责任和审计的稳定 API 供 Web、MCP、Skill、Agent、小程序和客户端共享；
- synthetic 数据也必须登记来源、许可和质量状态，并明确 `synthetic`；
- 治理汇总只能从权限过滤后的数据库事实计算，不能使用前端固定数字；
- 许可不明确、已暂停或已到期时采用拒绝/降级，不默认扩大使用范围；
- 质量问题不能静默改写源事实，修正和人工确认均保留记录。

## 当前首期范围

1. 数据资产和模式版本；
2. 数据契约及版本；
3. 电子资源许可 grant 与用途矩阵；
4. 质量规则、运行与问题；
5. stewardship 责任分配；
6. 对象来源追溯和治理汇总 API；
7. 版本化治理 synthetic seed；
8. Web 治理页迁移到真实 API；
9. 能力目录登记，预留 MCP/Skill/Agent 适配；
10. 权限、许可、审计、幂等和页面运行验收。

## OpenMetadata 重新评估触发条件

- 至少两个获授权真实数据源进入；
- 有数据库/字段/管道/仪表板等技术资产需要自动发现；
- 出现无法经济自建的字段级血缘或通用质量规模；
- 学校确认部署、SSO、搜索、数据库、调度和运维责任；
- 以当时稳定版本重新核验资源、升级、许可和安全。

## 退出方案

- 最小治理域持续满足需求：不部署通用目录；
- OpenMetadata POC 通过：作为技术元数据投影接入，权威治理不迁移；
- 学校已有其他目录平台：实现同一 `MetadataCatalogPort`；
- 外部产品退出时，可由 PostgreSQL 权威治理状态重新建立技术投影。

## 首期实现结果（2026-08-26）

- PostgreSQL `V9` 建立 12 张最小治理域表，覆盖域、资产/版本/字段、契约/版本、许可、质量规则/运行/问题、责任分配和治理变更；
- 权限边界通过 RLS、最小授权、当前身份审计读取函数和 append-only 历史实现；
- 版本化 `governance-demo-v1` seed 显式标记 synthetic，使用应用角色写入并通过连续两次幂等执行；
- FastAPI 发布治理驾驶舱、汇总、许可、质量、审计、数据资产追溯和知识对象来源追溯 API；
- Web 治理页已删除组件内固定指标和许可数组，改读生成客户端与真实 API；
- OpenMetadata 未部署，重新评估条件保持不变。

生产阶段仍需在真实数据与真实组织身份到位后完成合同台账导入、学校角色矩阵、备份恢复、真实源血缘覆盖和 OpenMetadata 条件触发评估。
