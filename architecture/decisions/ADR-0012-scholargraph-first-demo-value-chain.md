# ADR-0012：学者星图首次 Demo 价值链与范围

- 状态：已接受；SG-01、SG-02 已完成，SG-03 待启动
- 日期：2026-08-26
- 决策人：项目负责人
- 关联编号：D-12

## 背景

项目负责人已确认学者星图是首次 Demo 的核心。现有 `/scholars` 页面具有完整视觉原型，但业务事实、指标和证据来自前端 fixture；平台底层已有 PostgreSQL、FastAPI、搜索和图投影公共能力。需要确定一条既能展示价值，又能作为最终系统首个可运行版本继续演进的实施边界。

## 决策

采用 **“人才发现 → 事实画像 → 成果/项目/研究方向 → 合作网络 → 关系依据与来源追溯”** 作为首次 Demo 主价值链。

使用 `scholargraph-demo-v1` 版本化 synthetic 数据，通过 PostgreSQL 权威模型、RLS、证据、Outbox、OpenSearch/HugeGraph 可重建投影、FastAPI 公共能力和 React 页面贯通。学者星图增加薄的产品级读模型，但不建立独立数据底座。

SG-01 实现数据和公共读模型，SG-02 实现真实 Web 切片，SG-03 完成双后端、浏览器和演示验收。比较、纠错写入、人才评价/排名、推荐、报告、AI 和真实数据接入延后。

## 首次 Demo 延后能力及原因

### 人才排名、评价和发展潜力判断

这些结果属于任务画像和高影响管理判断，需要正式指标口径、比较群体、时间窗口、数据完整性、制度依据和专家确认。synthetic 小样本只能演示界面，不能验证公平性、稳定性或管理适用性；首次加入会把“知识基础设施价值展示”误导成“系统已经能够评价人才”。在真实数据、正式评价场景、责任部门规则和人工复核机制齐备后恢复。

### 学者比较任务

比较不是并排展示两个页面，而是需要可版本化的比较范围、指标口径、缺失值处理、同类群体和结果保存；如果形成长报告，还依赖 D-10 任务执行。SG-01 先固定单个学者事实与证据契约，避免把未定义口径固化到 API。至少两个真实业务比较场景和指标责任人明确后恢复。

### 纠错审批和报告导出

纠错是 governed write：需要真实身份、对象归属、受理人、状态机、冲突处理、审计和通知；报告导出需要模板版本、数据快照、许可检查、水印和异步产物治理。D-08、D-09、D-10 已延后，当前做“提交成功”只会形成伪流程。真实试点用户、审批责任和导出用途明确后恢复。

### AI 画像与合作推荐

AI 结果需要模型/提示词/工具版本、输入数据许可、评测集、幻觉与偏差控制、证据引用、人工确认和成本治理。当前 synthetic 数据量不足以验证推荐质量，也不能把固定输出称为 AI 洞察。先建立可核验事实与图关系，后续 AI 只能在这些公共能力之上生成受控分析。D-14 安全边界和首批评测任务确认后恢复。

### 真实学校数据接入

真实接入需要源系统责任人、正式接口、字段口径、数据授权、个人信息分级、增量更新、质量 SLA、许可和退出方案；这些组织事实当前未获得。提前写针对未知系统的连接器容易固化错误字段和权限假设。首次 Demo 用相同领域/API 链路的版本化 synthetic 数据验证产品价值，真实接入前恢复 D-06、D-08、D-09。

### 七类应用和五类角色入口的完整实现

它们是长期产品组合，不是一个可同时验收的首期切片。全面铺开会重复页面、稀释学者星图主叙事，并在身份、权限、流程和真实数据尚未就绪时制造大量空壳功能。SG-01 先建设协议无关 Scholar capability，未来各角色入口复用同一能力而不是复制业务逻辑；学者星图主链路通过并获得用户反馈后，再按价值和前置条件逐项开放。

## 必须保持的边界

- 学者星图是 SmartLib Knowledge Services 的应用，不是 SmartLib 总平台；
- PostgreSQL 保存规范对象、关系和证据，HugeGraph/OpenSearch 只保存可重建投影；
- synthetic 与真实数据使用同一领域和公共能力契约，只在来源与真实性标签上不同；
- 页面不得直接 import 学者业务 fixture，也不得硬编码管理指标；
- 事实画像、分析画像和任务画像分层，推断不得伪装为权威事实；
- 所有可见指标必须由当前可见对象/关系计算并保留口径；
- 无可见证据、许可不明或投影失败时不补造结果；
- 公共接口不暴露 Cypher、OpenSearch DSL 或存储产品执行标识；
- Web、API 及未来 MCP/Skill/Agent/小程序/客户端复用同一 capability；
- 不把 synthetic Demo 表述为已接入学校人事、科研或电子资源系统。

## 首次 Demo 验收重点

- 能从研究主题或姓名找到 synthetic 学者；
- 能打开事实画像并查看代表成果、项目和研究方向；
- 能展开至少一条跨院系合作网络；
- 能从研究方向或合作关系回到证据、来源和版本；
- PostgreSQL/HugeGraph 图查询和 PostgreSQL/OpenSearch 搜索结果满足同一业务断言；
- RLS、证据过滤和不可见路径泄漏为零；
- `SMARTLIB_WEB_DEMO_MODE=false` 时不回退到 fixture；
- 页面明确标注 synthetic 数据，不出现未实现按钮伪交互。

## 后果

### 正面

- 首次 Demo 形成可讲清、可点击、可追溯的核心价值链；
- 首批开发直接补齐最终系统的数据、能力和多入口契约；
- 复用已确认的 PostgreSQL、FastAPI、OpenSearch 和 HugeGraph 投影；
- 控制首次范围，不用伪指标填满六维画像。

### 代价

- 当前视觉原型中的部分数字和按钮需要删除或降级；
- 需要新增学者场景读模型和一组完整 synthetic 关系数据；
- 首次 Demo 不展示评价、排名、推荐、报告和 AI 等更强叙事。

## 后续演进

- 真实数据阶段恢复 D-06/D-08/D-09，接入身份、来源、许可与业务确认；
- 需要异步画像重建、导出或报告时恢复 D-10；
- 学术影响与发展变化只有在数据来源、口径和比较群体明确后进入；
- 比较、纠错和任务画像按正式业务流程逐项增加，不改变当前公共 Scholar ID 和 capability。

## SG-01 实施记录（2026-08-26）

- 建立 `scholargraph-demo-v1` manifest 和通过 `smartlib_api`/RLS 写入的幂等 seed；
- 写入 6 位 synthetic 学者、37 个规范对象、37 条来源引用、37 条证据、60 条关系和 60 个关系证据链接；
- 建立 `scholars` 产品读模型，并发布 `search_scholars`、`get_scholar_profile`、`get_scholar_network`、`get_scholar_evidence` 四个公共能力；
- 学者网络复用 GraphPort，公共接口不暴露 Cypher；能力目录、OpenAPI 1.0.0-alpha.5 和 TypeScript 客户端已同步；
- seed 连续运行两次后计数不变；数据库验收通过，包含跨院系合作路径、待确认分析关系和逐关系证据覆盖；
- 历史运行验证中 PostgreSQL 与当时的 Neo4j 对同一学者一跳网络均返回 11 个节点、10 条关系和 10 个证据引用；Neo4j 已由 ADR-0013 替换；
- 统一 PostgreSQL 搜索投影已能检索 synthetic 学者；OpenSearch 同场业务验收保留到 SG-03；
- 后端 Ruff 与 21 项测试通过；Web 生成契约、TypeScript、lint、6 项测试和生产构建通过；
- SG-01 完成时 `/scholars` 仍读取 fixture；该历史边界已由下列 SG-02 实施记录关闭。

## SG-02 实施记录（2026-08-26）

- `/scholars` 已从 `DemoWorkspaces` 和 `DemoBoundary` 迁出，页面不再读取 `scholars`、`evidenceItems` 或其他学者业务 fixture；
- 新建 Scholar 产品组件，通过生成客户端和 TanStack Query 读取学者目录、事实画像、一跳知识网络和按需证据追溯；
- 姓名关键词和院系筛选由 Scholar 公共 API 执行，页面计数、成果、项目、合作者和研究方向均来自当前可见关系；
- 画像只展示基本信息、方向、代表成果、项目与可见关系计数，删除比较、纠错、导出、画像完整度、影响力和发展趋势等未确认能力；
- 网络页面显示实际后端、投影版本、节点、关系、事实类别、审核状态和证据数；投影不可用时显示独立失败状态，不回退硬编码图；
- 证据抽屉按需请求真实 evidence bundle，显示来源、引用、数据集版本、观察时间、事实类别、审核状态、置信度与 synthetic 标签；
- 修正 Scholar 公共标识契约：详情、网络和证据端点接受 `SL-DEMO-xxxx` 公共编号，同时兼容规范对象 UUID；Web 只用公共编号调用；
- OpenAPI 1.0.0-alpha.6、能力目录与 TypeScript 客户端已同步；新增组件、架构和浏览器测试，覆盖真实搜索、画像、图、证据、明暗主题、390px 移动端与 axe 无障碍；
- `SMARTLIB_WEB_DEMO_MODE=true` 和 `false` 构建均通过容器浏览器验收，关闭 demo mode 不会回退 fixture；
- SG-02 只证明真实 Web 切片已形成。PostgreSQL/HugeGraph 与 PostgreSQL/OpenSearch 双后端一致性、失败演练和最终演示脚本仍属于 SG-03。
