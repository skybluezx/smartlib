# ADR-0014：Demo 对象存储采用 MinIO Community

- 状态：已接受（仅限本地开发与 Demo）
- 日期：2026-09-02

## 背景

SmartLib 需要保存论文全文、来源文件、处理产物和证据包等大对象。PostgreSQL 只保存对象元数据、受控存储地址、校验值、版本和审计关系，应用层通过 S3 API 访问文件，避免把大文件写入关系数据库。

## 决策

当前本地开发与 Demo 使用 MinIO Community 作为 S3 兼容对象存储：

- 从 MinIO 官方仓库最后提交 `7aac2a2c5b7c882e68c1ce017d8256be2feea27f` 构建；
- 使用 Compose 命名卷 `smartlib-minio` 持久化对象；
- 自动创建 `smartlib-publications` 桶并启用对象版本控制；
- 应用只依赖 S3 接口和配置，不把 MinIO 私有接口写入领域逻辑；
- 论文全文由 Platform API 接收，服务端完成 PDF 校验、SHA-256 计算、内容寻址和 S3 写入，浏览器不持有 MinIO 凭据；
- PostgreSQL 只登记对象引用、校验值、大小、版本化补充证据和审计关系；对象内容保存在 MinIO；
- 镜像保留上游许可证与源码提交标记。

## 后果

本地 Demo 获得可运行的全文对象存储，容器重建不会删除存储卷中的对象。后续可在不改变论文领域模型的前提下，替换为学校对象存储、Ceph RGW 或其他合规 S3 服务。

MinIO Community 上游仓库已停止维护，并以 AGPLv3 提供源码；当前方案不作为生产选型结论。试点生产前必须另行评估安全补丁来源、许可证义务、专用服务账号、TLS、服务端加密、备份恢复、多副本和高可用，并以新 ADR 确认最终实现。

## 验收

- MinIO 容器健康检查通过；
- 主机端 S3 健康接口与管理控制台返回 HTTP 200；
- `smartlib-publications` 桶可读；
- 桶版本控制状态读回为 `Enabled`；
- 镜像内源码提交和许可证标记可审计；
- 现有 Web 与 Platform API 健康检查继续通过。
- 从论文核验页面选择 PDF 后可完成“上传对象→登记补充证据→进入增量核验”的完整链路；
- 数据库登记失败时，新建对象版本可被永久回滚，不留下无主测试对象。
