# ADR-0003：Python/FastAPI 作为平台核心主路线

- 状态：已接受
- 决策日期：2026-08-25
- 关联决策：D-01

## 背景

SmartLib 的首版必须是最终平台的可持续起点：所有 Web、API、MCP、Skill、Agent、小程序和客户端共享同一领域能力、授权、证据、任务和审计语义。首期采用模块化单体，并以 PostgreSQL 18 保存权威状态。

## 决策

平台核心采用 Python 3.14 与 FastAPI 0.141.x。首个工程基线固定为 FastAPI 0.141.1、Pydantic 2.13.4、Uvicorn 0.52.4、Psycopg 3.3.4 和 psycopg-pool 3.3.1。

平台不是“路由加 SQL”的脚本集合，而是具有强制边界的模块化单体：

- `foundation`：配置、数据库、身份上下文、错误和追踪；
- `source`：来源登记与授权状态；
- `knowledge`：知识对象、来源证据与领域事件；
- `operations`：任务、健康与运行状态；
- `audit`：追加式审计；
- `entrypoints`：REST/OpenAPI 等协议适配，不拥有业务规则。

应用通过独立 PostgreSQL 登录角色运行；每个事务写入调用者上下文并接受 RLS 约束。领域状态与 Outbox 事件必须在同一事务提交。Flyway 仍是唯一数据库结构迁移入口，应用启动不得自动改表。

## 约束

1. Ruff、类型检查、模块依赖测试、契约测试和数据库集成测试是持续集成硬门槛。
2. 路由只能调用模块应用服务，不能跨模块直接操作表。
3. 数据/AI 重任务以后作为独立工作进程部署，但复用能力契约，不能绕过平台核心写权威状态。
4. 开发身份头仅限隔离的 synthetic Demo；D-08 已在 Demo 阶段延后，进入真实用户/数据、试点生产或外部接口开放前必须恢复并替换为正式身份适配器。
5. 搜索、图、向量和模型是可替换投影或适配器，不进入权威领域核心。

## 后果

首版接口和数据/AI 协作速度更快，技术栈更集中；代价是必须自行维护 Java/Spring Modulith 原本可提供的模块结构保护。因此架构测试和代码所有权不能在后续交付中降级为可选项。

## 复审条件

出现以下任一证据时复审，但不因偏好重写：模块边界连续失守；性能或隔离需要独立扩缩容；学校统一技术规范要求其他运行时；核心团队无法维持 Python 工程质量门槛。
