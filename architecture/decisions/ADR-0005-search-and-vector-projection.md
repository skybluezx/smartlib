# ADR-0005：搜索与首期向量投影路线

- 状态：已接受（POC 主路线；首版实施产品仍需 POC 证据）
- 日期：2026-08-25
- 决策人：项目负责人
- 关联编号：D-04

## 背景

SmartLib 需要为 Web、Public API、MCP、Skill、Agent、小程序和客户端提供同一套权限感知检索能力。PostgreSQL 18 保存权威状态，搜索与向量只保存可重建投影。当前缺少足以评价中文相关性、许可过滤和容量的授权真实样本，不能直接把架构建议转成生产选型。

## 候选方案

1. OpenSearch 3.8.x：全文、聚合、向量和混合查询集中，Apache 2.0，可独立扩容；代价是新增集群运维和索引治理。
2. PostgreSQL 18 FTS + pgvector 0.8.6：组件最少、可复用 RLS 和事务运维；中文分词、复杂聚合、权威库资源竞争和高选择性 ANN 过滤必须实测。
3. Elasticsearch 9.4.x：已有学校平台和订阅时有价值；发行许可和所需安全/混合能力权益必须采购核验。
4. 专用向量库：只有现有候选无法满足真实召回、过滤、延迟或容量目标时再评估。

## 决策

确认 OpenSearch 3.8.x 为 D-04 真实 POC 主路线，以 PostgreSQL 18 FTS + pgvector 0.8.6 为同场基线。本 ADR 接受的是 POC 路线、架构边界和选择方法，不代表 OpenSearch 已经通过 SmartLib 真实数据验收。POC 通过后应补充实施记录；未通过则记录否决证据并采用 PostgreSQL 基线或重新决策。

成立前提：

- 使用学校授权的代表性数据和专家标注查询；
- 权限和许可过滤零泄漏；
- OpenSearch 在相关性、聚合、独立扩容或资源隔离上的收益足以覆盖新增运维成本；
- 电子资源合同允许进入索引的字段及向量化用途；
- 固定具体 3.8.x 补丁版、插件版本和镜像摘要。

首期不引入独立向量库。Elasticsearch 仅在学校能提供准确平台版本、订阅权益和运维责任时加入 POC。

## 后果

### 正面

- 不用产品宣传替代 SmartLib 真实数据证据；
- 搜索产品可以替换，上层入口与领域语义保持稳定；
- 先验证最危险的权限泄漏、中文相关性和重建问题；
- 保留低复杂度 PostgreSQL 首版路线，不为展示价值过早承担集群成本。

### 负面与债务

- 在 POC 完成前需要维护两套适配器或最小实验实现；
- 需要学校提供授权样本、许可矩阵和专家标注时间；
- 嵌入模型、切片、重排和图召回仍需后续独立决策。

### 退出/替换方案

- 若 OpenSearch 未达到安全/质量门槛，首版采用 PostgreSQL 搜索适配器，并保留独立搜索迁移事件和索引文档规范；
- 若学校已有合规 Elastic 平台，则以同一验收集加入测试，不改变能力契约；
- 若未来向量规模或过滤性能成为经验证瓶颈，通过 `VectorIndexPort` 接入专用向量库并新建 ADR；
- 所有投影可由 PostgreSQL、对象存储和版本化事件重建。

## 必须保持的产品无关契约

`search_knowledge` 输入至少包含：查询文本、对象类型、结构化过滤、分页、召回模式和调用用途。身份、角色、组织、网络与许可上下文由可信网关注入，客户端不得自行声明为可信事实。

结果至少包含：稳定对象 ID、对象类型、标题/摘要、证据 ID、对象版本、投影版本、召回通道和可解释信息。结果不能返回未经许可的原文或通过分面计数泄漏受限对象存在性。

## 验证方法

以《D-04 搜索检索 POC 验收方案 v1.0》为准，至少验证：

- 中文/CJK/ICU 与 PostgreSQL 中文方案的同查询集相关性；
- 精确标识符、别名、短语、中英混合、语义改写、过滤和分面；
- 每一查询模式、聚合、分页和解释接口中的零未授权命中；
- BM25、向量、RRF 和分数融合的 NDCG@10、MRR@10、Recall@50；
- 高选择性权限过滤下的 ANN recall 与结果数；
- p50/p95 延迟、吞吐、CPU、内存、存储和索引耗时；
- Outbox 幂等、权限变更失效、删除传播、全量重建、别名切换和故障恢复；
- 同一能力经 API 调用，并验证未来适配器不需要理解底层 DSL。

## 首期实施记录（2026-08-25）

已完成 POC 基础设施阶段，不等同于真实数据选型验收：

- 发布产品无关的 `SearchPort` 与 `search_knowledge` API；Web、Public API 和未来 MCP、Skill、Agent、小程序、客户端共享同一领域契约；
- PostgreSQL 18 权威对象通过 Outbox 投影到 PostgreSQL 检索表和 OpenSearch，两个投影分别记录消费回执，失败互不冒充成功；
- 固定 OpenSearch `3.8.0` 本地 POC 镜像，实测镜像摘要为 `sha256:bcc1797519726ceb6d651d4a3e60b7c30da91793914a8dfe75fd441d4f641509`；
- 创建严格映射、版本化索引和读写别名；词法查询已通过真实 API，公开对象可见，其他用户私有对象的命中和分面计数均为零，拥有者可见；
- 以隔离临时索引验证 4 维 `knn_vector`、Lucene HNSW 和查询内权限过滤机制；测试后已删除临时索引；
- 默认运行后端仍为 PostgreSQL；`semantic` 与 `hybrid` 模式在嵌入模型、切片和融合策略确认前显式返回不可用，不使用伪向量结果。

仍未完成：学校授权真实数据集、中文分析器对比、嵌入模型、专家标注、相关性指标、容量曲线、权限撤销 SLO、重建/故障恢复演练和总拥有成本。完成这些证据前，不得把本记录解释为 OpenSearch 生产验收。
