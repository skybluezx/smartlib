# 合作结构评价方法 v1

## 使用边界

这是一份当前论文样本的合作结构证据，不是正式团队认定或科研质量排名。现有代表作样本存在选择偏差；尚无完整学校历年成果、全部申请结果与人员历史归属，不支持全校格局、申报成功率、因果效应或团队持续性结论。

## 数据与范围

PostgreSQL 当前 `analysis_relation` 与业务对象提供事实，沿用 `analysis_state_eligible`，不改变待核验数据参与分析规则。HugeGraph 不是本算法的执行器。人员按对象编号、论文按对象编号去重；重复关系不重复计权。全局时间、项目种类、机构、学者、自定义范围先共同选出论文；缺作者关系的论文保留在范围分母与缺失清单。

每篇论文所有已关联作者构成无向合作对，不含自环。相同两人每篇论文只计一次，权重为共同论文数。全部节点包括孤立作者。基准网络最低共同论文数固定为1，不先截取强边。下方机构/学者探索、外部合作者开关、显示阈值、连线数、隐藏节点、最少簇人数只影响可视化，不改变评价结果。修改上方论文范围才重新分簇。

完整指“当前已入库且符合分析范围的数据”，不表示论文的每位作者已经完整入库或学校成果全覆盖。

## 算法与参数

标准 NetworkX 3.6.1 Louvain 多层模块度优化，方法版本 `cooperation-louvain-v1`。权重=去重共同论文数；resolution=1；seed=42；threshold=1e-7；不限制聚合层数。排序固定节点/边输入，输出按簇人数降序、成员编号排序编号。种子和分辨率是预设基准，不是经验验证最优参数。

模块度 Q 使用加权无向配置模型。Louvain 是启发式，不保证全局最优；存在分辨率限制、潜在内部不连通群体，展示每簇内部连通分量供核实。图上布局仍可使用力与间距调整，但人员的簇编号由后端指定，不由坐标或前端截断图重新计算。

## 稳定性与敏感性

固定基准之外：种子43/44/45/46；分辨率0.8和1.2；每篇每条边权重1/(作者数−1)的大作者组校正。其他条件不变。

全局划分比较用调整兰德指数 ARI，同一节点全集、置换校正，可为负。单簇成员稳定性是四个种子运行中，与该簇最相似群体的 Jaccard 相似度均值。两者不代表真实性概率；不设未经业务验证的合格线。不把高模块度写成高科研质量。

## 统计分母与证据

- 内部合作对：两个端点都在该簇的去重人对。
- 对外合作对：仅一个端点在该簇的人对。跨簇总和会重复，不能直接作为全网人对数。
- 密度：内部人对数 / [人数×(人数−1)/2]；单人不适用。
- 内部联系权重占比：2×内部边权重 / (2×内部边权重+对外边权重)；无边不适用。
- 共同论文：至少有两位簇内作者的去重论文；单人簇单独标为个人论文。跨簇论文可重复出现。
- 孤立作者：完整基准图的度为0，不是被截断后暂时无边。

页面可下钻全部成员与论文，导出 JSON 包含全范围论文编号、缺失作者清单、实际作者输入、作者关系编号/版本、机构集合、全部成员分配、参数、软件版本与敏感性结果。输入和参数 SHA256 指纹用于发现变化；名称更新也改变指纹。导出是用户持有的冻结证据，不等于服务器永久存档。

## 科研评价流程

先核对范围完整性和人员消歧，再查看结构与稳定性，逐簇回看成员/论文并邀请科研部门和学科专家确认群体解释。正式评价还需作者贡献、时间序列、领域归一化成果表现及可比样本。不得用簇人数/密度直接打分或建立人员奖惩排名。需要跨期比较时，固定方法与数据口径，保留每期冻结输入，再按成员交集匹配群体，不能按展示编号直接匹配。
