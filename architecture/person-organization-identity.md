# 人物与机构专表（V42）

2026-09-07 已应用到本地运行系统，API 与网页已更新。本文不表示远程服务器已部署。

## 六张表的分工

| 表 | 定位 | 关联 |
|---|---|---|
| person_profile | 人物详情：有依据的姓、名、姓名首选语言 | object_id 同时为主键及 knowledge_object 外键 |
| person_identifier | 人物外部标识；当前审核入口支持 ORCID | object_id 指向 person_profile |
| person_name_variant | 原始来源姓名和审核认可的其他姓名 | object_id 指向 person_profile |
| organization_profile | 机构详情：机构类别、国家或地区代码；机构和部门共用 | object_id 指向 organization/department 类型对象 |
| organization_identifier | 机构外部标识；当前审核入口支持 ROR | object_id 指向 organization_profile |
| organization_name_variant | 原始来源名称、简称及其他名称 | object_id 指向 organization_profile |

统一对象表继续保存对象身份、规范名称、可见性和版本。机构上下级、人物任职和论文中的作者机构对应仍使用关系体系；本次不建立重复的关系权威来源。论文署名记录与经过消歧的人物身份仍是两个层次，全文出现的 ORCID 不会自动成为人物正式标识。

## 接入与变更

新建人物、机构或部门对象时，数据库自动建立对应详情行及来源名称行。现有 58 位人物已回填 58 条档案、58 条来源姓名，每条姓名都有 source_reference 关联。迁移没有推断姓、名、语言或外部标识。

GET /api/v1/identities/{object_id} 返回详情、有效标识和名称。统一目录对象详情也返回专表信息，目录和学者搜索支持有效别名与标识；搜索投影读取专表名称。

网页“知识中枢 → 数据变更”可选择人物、机构或部门，修改其专属字段。所有修改通过 change_submission / change_proposal 提交，审核接受后由领域适配器写入专表，同一次对象更新只推进一次对象版本。版本冲突不覆盖新数据。变更关联 submission_id 和 evidence_id，并记录 entity_revision 历史；通过统一对象事件更新搜索投影。

原始来源名称和可调整的别名分别保存。撤销标识或别名会标记失效，保留记录及历史。标识在有效状态下跨对象唯一，同一对象每个命名空间只能有一个有效值。ORCID 校验格式与校验位；ROR 目前校验格式。这些校验不等于外部权威身份确认，审核仍需核对来源。

六张表读取权限跟随统一对象可见性；写入要求变更决定权限。对象创建触发器仅初始化空档案，不授予额外读取权限。
